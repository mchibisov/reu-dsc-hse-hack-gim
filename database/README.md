# GIM database MVP

Компонент PostgreSQL и приватных файлов для VK-бота Государственного исторического музея.
Бот, LLM gateway, генераторы PDF/XLSX и кабинет подключаются через этот контракт.

- [Контракт Python и форматы данных](docs/contracts.md)
- [Переход бота ветки Vova на новый контракт](docs/integration-with-bot.md)
- [Проверки и ограничения стенда](docs/verification.md)
- [PNG-схема реализованной БД](docs/database-schema.png)

12 таблиц `gim`: пользователи и сотрудники; наборы и банк вопросов; анкеты, точные вопросы и версии ответов; оценки и файлы; inbox/outbox и аудит. Частная схема не публикуется через Data API. Нет доступа из браузера к PostgreSQL/Storage с сервисными ключами.

PostgreSQL хранит весь постоянный контекст. Redis/ARQ исполняет фоновые задачи; издатель восстанавливает незавершённые намерения из outbox. Отдельной очереди исполнения PostgreSQL нет.

В Supabase Free создан проект `gim-volunteers-mvp` (`bytwrnvnujzscfjfmdhm`, Frankfurt), применены миграции, создан приватный bucket `gim-private`. Рабочие пароли/LOGIN-роли, настоящий VK group ID, первый администратор и утверждённая конфигурация набора должны быть настроены командой перед интеграцией. Реальные анкеты в облако не загружались.

Все команды ниже выполняются из `database/`; корневой Compose сохранён от бота Vova и использует другой, прежний контракт. Не подключать две очереди к одному live-набору.

## Быстрая проверка на одноразовой локальной БД

```sh
uv sync --extra test --extra materials
# TEST_DATABASE_URL должен указывать на отдельную PostgreSQL >=16, не production.
DATABASE_ADMIN_URL="$TEST_DATABASE_URL" uv run python -m gim_db.migrate
uv run pytest -q
# Настоящий Redis/ARQ проверяется при наличии TEST_REDIS_URL (отдельный Redis).
TEST_REDIS_URL=redis://127.0.0.1:56379/0 uv run pytest -q tests/test_redis.py
```

Тесты создают синтетические записи и сервисные роли в тестовой БД; не запускать их на рабочем наборе. Проверка качества оценки требует предсказаний команды на экспертной разметке; схема сама по себе его не доказывает.

Исходные DOCX/PDF/XLSX и персональные ответы не включены в репозиторий. Загрузчики работают с локальными оригиналами, не отправляя их третьим сторонам.
