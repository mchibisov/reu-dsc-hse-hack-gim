# S011 — проверка реального VK с предоставленным токеном

Состояние: выполняется. Пользователь предоставил токен сообщества242476311 и поручил тестировать бота. Проверяем реальные read-only API VK без записи токена/ответов с персональными данными в журнал. Локальный .env закрыт .gitignore; пустые RECRUITMENT_ID и три runtime DSN не объявляются рабочими. Production gateway не запускать параллельно Callback; данные/настройки сообщества не сбрасывать. Для полной анкеты требуется runtime БД и активный набор, для анализа также ключ выбранной модели.

## Подтверждено реальными API

- Токен действителен, имеет messages/manage/docs и другие права; целевое сообщество найдено. [live-result.json](live-result.json), [проверка](check_live.py).
- Два Callback-сервера: один unconfigured, второй status=ok с ожидаемым host gim-volunteer-bot.vercel.app. Настройки рабочего Callback: message_new=true, API5.199. Наличие старого unconfigured сервера само по себе не доказывает ошибку действующего.
- Messages API доступен. В пяти последних диалогах обнаружены исходящие сообщения бота; ближайшее по времени примерно49минут до проверки, не новый ответ на текущий тест. В одном диалоге виден прогресс17/19,18/19,19/19. Это доказывает ответы старого банка/версии в тот момент, но не устанавливает текущий deployed SHA. [Обезличенный результат](recent-result.json), [скрипт](check_recent.py). Тексты, имена и peer IDs не сохранены.
- В исторических фрагментах команды старта следующий исходящий ответ приходил через1–8секунд; это наблюдение существовавших диалогов, не активный тест/SLA и не доказательство отсутствия задержек на других шагах.

## Что пока не выполнено и почему

Токен сохранён только в ignored .env; автоматическая проверка подтвердила env_tracked=false и token_in_tracked_files=false. Локальный check-db завершился exit2 с точной диагностикой отсутствия DATABASE_BOT_URL/DATABASE_WORKER_URL/DATABASE_STAFF_URL/RECRUITMENT_ID ([startup-utf8.log](startup-utf8.log)); LLM_API_KEY также пуст. Исходный startup.log имеет повреждённый текст из-за кодировки вывода, повтор с PYTHONIOENCODING=utf-8 читается правильно. Это не изменялось в приложении.

Сквозная новая анкета пока не запущена: ожидается VK ID тестирующего и входящее «Начать» от него. Токен сообщества отправляет сообщения от сообщества, а incoming принимает пользовательские события; исходящее сообщение самому сообществу не заменяет пользовательский старт. Запрос VK ID отправлен пользователю. Другим участникам сообщения не отправлялись, transport/Callback не менялись, рабочая БД/облако не обновлялись. Для обновлённого18-вопросного запуска нужны существующие runtime-подключения и контролируемый rollout по README.
