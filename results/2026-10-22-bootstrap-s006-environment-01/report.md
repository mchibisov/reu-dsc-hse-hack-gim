# S006 — первичная диагностика и чистая установка

Состояние: завершено с ограничением Docker. Проверка техническая, без продуктовой гипотезы.

Контекст: исходный checkout ed0af3e чистый; git fetch и merge --ff-only обновили его до 3f95b67, соответствующего handoff. Приложенные документы прочитаны как контекст, актуальные критерии взяты из сообщения пользователя.

Наблюдения до установки: системный python не найден в PATH; старая внешняя venv использует Python 3.14, её stdlib недоступна в sandbox (encodings). Встроенный Python 3.12.14 доступен, psycopg не установлен. Docker CLI установлен, daemon не запущен. Доступен PostgreSQL 18.4. План: новая venv внутри checkout и отдельный локальный кластер PostgreSQL; чужие сервисы не останавливаются.

Сетевой git fetch выполнен с разрешённым расширением sandbox; обычный вызов был заблокирован сетью. GitHub connector авторизован как mirovif; авторство mchibisov из handoff на этой машине не переносится автоматически.

После разрешённого сетевого доступа установка в новой venv Python 3.12.14 завершилась успешно: [install.log](install.log). Первая попытка pip была заблокирована сетью sandbox (WinError 10013), не ошибкой зависимостей проекта.

Кластер инициализирован в игнорируемом runtime/s006-pg/data; pg_ctl в sandbox не смог создать restricted token, затем разрешённый запуск успешно поднял только 127.0.0.1:55439. Проверки БД сохранены отдельно.

Локальный Docker Desktop запущен в фоне, однако Engine отвечает 500 на _ping/version: [docker-build.log](docker-build.log). Образ не собран; это ограничение среды, а не успешная проверка Dockerfile. Compose config проверен отдельно без daemon. Право git push проверено --dry-run, main доступна на запись.

Вывод: зависимости установлены; запуск приложения подтверждается следующими отчётами, локальная Docker-сборка не подтверждена. Дальше — CI build/smoke.
