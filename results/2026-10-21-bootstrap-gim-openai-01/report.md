# Проверка выданного ключа на официальном OpenAI API

- Дата: 2026-10-21, Europe/Moscow.
- Основание: пользователь просит попробовать предоставленный «ключ от GPT»; сторонний провайдер/base_url не указан.
- Метод: один GET https://api.openai.com/v1/models с Bearer; ключ только в исключённом .env, в отчёте только status/error code/type.
- Критерий: HTTP 200 подтверждает доступ к каталогу, не генерацию; HTTP 401/invalid_api_key означает отказ официального endpoint; региональная/сетевая ошибка не доказывает неправильность ключа.
- Ограничения: реальные анкеты не отправляются, настройки работающего VK-бота не меняются; ключ не проверяется на угаданных сторонних сайтах.
- Состояние: подготовлен.

## Результат

- Состояние: завершён, официальный endpoint отклонил ключ.
- Факт: GET /v1/models вернул HTTP 401, error_code=invalid_api_key, error_type=invalid_request_error.
- Доказательства: [access.json](artifacts/access.json), [ruff](artifacts/ruff.txt).
- Вывод: доступ к официальному OpenAI API с этим значением не подтверждён; отказ не проверяет валидность ключа для неизвестного стороннего сервиса.
- Ограничения: генерации не было, реальные анкеты не передавались, активные LLM_API_KEY и LLM_MODEL остались пустыми, перезапуск VK не выполнялся.
- Следующий шаг: узнать у пользователя сервис-эмитент и документированный base_url; не отправлять ключ на угаданные домены.
- Метод подтверждён официальной документацией: https://developers.openai.com/api/reference/resources/models/methods/list
