# Проверка IT-критериев и исправления — 22.10.2026

Актуальная основа `main` загружена fast-forward с ed0af3e до 3f95b67. Проверка выполнена на Windows, чистой Python 3.12.14 и отдельной локальной PostgreSQL 18.4; рабочие анкеты и облачный deployment не изменялись.

## Что исправлено

1. Чтение русской рубрики и операторских JSON зависело от системной кодировки: на Windows возникали ошибки декодирования или повреждались русские строки. Теперь явно используется UTF-8 с поддержкой BOM в рубрике, импорте набора, файле runtime-логинов и JSONL расчёта метрик.
2. Приватная JSONL-выгрузка писалась в системной кодировке и падала на Unicode вне cp1251. Теперь она записывается в UTF-8. Исходные данные не заменяются и не усекаются.
3. Тест `.env` сам создавал файл в системной кодировке вместо требуемой UTF-8; исправлена fixture, загрузчик не ослаблен.
4. Корневой Dockerfile не включал `config/`: такой образ не смог бы начать новую анкету со стандартной рубрикой. Добавлено копирование конфигов; Compose уже использовал корректный Dockerfile.shared. В CI добавлены проверка рубрики корневого образа, сборка shared-образа и проверка его CLI.
5. Общий `pytest` из корня не подхватывал `asyncio_mode` вложенного pyproject: 47 SQL-тестов завершались ошибкой до исполнения. Добавлен корневой pytest.ini, включающий оба набора тестов.
6. Добавлены регрессии Unicode/BOM и полного операторского bootstrap с синтетическими DOCX/PDF. Временные LOGIN удаляются в finally; замечание независимого code review устранено.
7. Добавлена Windows/Python 3.12 проверка приложения в GitHub Actions, обновлена инструкция кодировок.
