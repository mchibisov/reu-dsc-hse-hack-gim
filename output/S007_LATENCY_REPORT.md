# Задержка VK — исправление без смены модели

Пользователь подтвердил задержку 20 секунд–3 минуты и на обычных вопросах. Воспроизведены три дефекта dispatcher: idle обработчики завершались во время медленного AI; все general lanes могли заняться анализами; при remaining<185 не обрабатывались даже обычные vk.incoming. Общая аренда при этом не позволяла запустить нового worker.

Исправление: свободные lanes остаются доступны при активных задачах; выделены доставка и диалог; короткий бюджет ограничивает анализ, а не все входящие сообщения; TaskGroup останавливает siblings до освобождения общей аренды. Модель, формула, SQL FIFO и данные сохранены. Миграция для S007 не нужна.

Проверка: **251 passed in 26.99s**, без skip. При max_size=2 у всех pools, как в production, ответ во время одного/трёх queued анализов занял **0.671/0.672с** и был отправлен до завершения AI. Это локальная PostgreSQL с управляемыми AI/VK-границами, не production SLA. Независимое review замечаний не нашло.
