# Как повысить оценки: кто и что делает

Состояние на 22.10.2026. Оценки из JURY_ASSESSMENT.md — самооценка, не обещание баллов жюри.

Не обещать 100% |
| **P0 — воспроизводимый запуск** | Обновить README, проверить команды, подготовить новую тестовую БД и прогнать bootstrap без рабочих данных | Для полностью независимого теста нужен второй человек с доступом к своим VK/Supabase/Polza/Vercel либо выданной тестовой среде | Дать ему README и не подсказывать устно; записать место первой ошибки. Человеческий замер пока не проведён |

## Что можно сделать технически без нового решения музея

- Улучшать тексты ошибок и навигацию по конкретным результатам пользовательских тестов.
- Добавлять регрессионные проверки найденных багов, выполнять security review и проверять восстановление на изолированном стенде.
- Подготавливать отчёты по действующей формуле и разбирать ошибки на разрешённых диагностических данных.
- Готовить мониторинг и backup-скрипты после выбора доступного назначения, не меняя работающую инфраструктуру вслепую.

Эти работы не считаются выполненными только потому, что перечислены здесь. Новая независимая точность не появится от повторного прогона уже просмотренных контрольных анкет.

## Что сделать команде сейчас

1. Пройти анкету двумя новыми тестировщиками на телефонах и прислать время, скриншоты непонятных мест и UUID тестовых анкет.
2. Дать README второму разработчику для чистого развёртывания на отдельной среде.
3. Попросить куратора оценить полезность карточки и XLSX; обсудить 10–15 диагностических расхождений и веса формулы.
4. Назначить ответственного за эксплуатацию, согласовать backups, бюджет/квоты и правила персональных данных.
5. Записать короткую демонстрацию и отрепетировать ответ про ограниченную экспертную точность.
