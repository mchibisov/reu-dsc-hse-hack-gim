# Исправление реальной задержки VK — 22.10.2026

## Причина и границы вывода

Сообщение VK от 08:04:01 UTC поступило в PostgreSQL только в 08:07:20.134: задержка входа 199.134 секунды, обработка после получения 0.273 секунды. Несколько других входящих событий задержались на 15–20 секунд. Логи Vercel подтверждают позднее поступление HTTP-запросов; точный сетевой узел задержки не установлен. Прямые синтетические запросы к Callback не проверяли этот участок и потому давали слишком оптимистичную картину.

## Что изменено и запущено

VK server №2 переключён на `https://bytwrnvnujzscfjfmdhm.supabase.co/functions/v1/vk-callback`, статус VK — `ok`. Supabase Edge проверяет группу и SHA-256 отпечаток прежнего секрета, затем передаёт событие в существующий Python Callback Vercel. Ответ `ok` выдаётся только после его успешного ответа, то есть после записи в PostgreSQL. Новых потребителей очереди и дублирующего Long Poll нет. Схема БД и ответы не менялись.

Edge ограничивает тело 128 KiB, запрещает редиректы, использует фиксированный upstream и таймаут 2.5 секунды. При сбое возвращает 503 для повтора VK. Секрет и ответы в лог не пишутся; DB-ключи Edge не нужны. JWT отключён только для webhook с собственной проверкой секрета. Актуальный код подтверждения получен через VK API; подтверждение Edge отвечает локально, без зависимости от Vercel.

При ConnectTimeout/ConnectError первых двух попыток отправки сообщения пауза очереди сокращена с 5 до 0.5 секунды. Иные ошибки, ограничения VK, ограничение числа попыток и порядок сообщений сохранены.

Production Vercel: `dpl_EFoDxKK8FUKznK4EFckuUYLku4xt`, READY, fra1. Edge `vk-callback`, версия 2, ACTIVE.

## Конфигурация для переноса

Исходники: `database/supabase/functions/vk-callback`. `deployment-config.example.json` показывает структуру конфигурации. При развёртывании используется приватный `deployment-config.json`: числовой groupId, SHA-256 отпечаток VK_CALLBACK_SECRET, текущий код подтверждения VK и адрес своего Vercel /callback. Файл не публикуется в Git. Индекс импортирует его и запускает handler; функция развёртывается с verify_jwt=false, поскольку аутентификация webhook выполняется внутри handler. При смене секрета нужно одновременно обновлять отпечаток Edge, секрет Vercel и настройки сервера VK. Локальный Docker этого дополнительного входа не требует.
