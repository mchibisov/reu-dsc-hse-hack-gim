# Объединение MVP — 21.10.2026

## Какие части выбраны

- БД Макса: private PostgreSQL-схема `gim`, пять миграций, роли и Repository. Миграции не изменялись.
- VK Вовы: клиент, Long Poll, свежий OpenAI-compatible LLM-клиент и логика проверки заданной рубрики.
- Общая интеграция: shared gateway, сохранение диалога, SQL worker, staff ACL и XLSX.
- Из независимого прототипа использован подход к фильтрации входа LLM и проверке цитат. Его SQLite/SQLAlchemy-хранилище, фиксированная предварительная рубрика и отдельная очередь не заменяют PostgreSQL. Секретный Excel-код не перенесён.

Общая интеграция уже содержит исходную БД Макса и предыдущую VK-версию. Свежий VK-коммит объединён обычным merge без конфликтов. Независимый прототип имеет отдельный корень истории: его история присоединяется с сохранением выбранного shared-дерева, а полезная логика адаптирована к UUID и контракту общей БД. Это осознанный выбор одного runtime, не механическое объединение двух схем данных.

## Что исправлено при объединении

1. Вместо заглушки анализа — вызов модели, проверка фиксированных критериев, точных цитат и целого балла 0–3, сохранение через Repository с защитой аренды.
2. Уточнения получают историю содержательных ответов, библиотеку и направления; новый вопрос требует проверяемой цитаты и сохраняется до отправки. При недоступности модели анкета продолжается с библиотечными уточнениями.
3. Ошибка анализа и отсутствующий ключ не подтверждаются как успешная обработка и не создают нулевой балл.
4. Повтор отправки не позволяет следующему вопросу обогнать сообщение того же получателя; другой кандидат не блокируется. Неактуальный вопрос не отправляется повторно.
5. Сотрудник видит резюме, основания балла и интервью-вопросы; Excel включает сохранённую оценку и исходные ответы.
6. Основные Dockerfile, Compose, README и шаблон окружения ведут на Supabase runtime. CI запускается для main и pull request.

## Выполненные проверки

- Все 111 корневых unittest проверены: 77 без БД, 30 legacy DB-тестов на отдельной public тестовой БД, 4 shared DB-теста на отдельной private БД. Shared suite целиком: 51 тест успешно.
- 38 pytest для private БД успешно, включая новый регрессионный тест порядка исходящих сообщений и проверки 50 параллельных кандидатов.
- Полный путь в private БД: согласие → музейная анкета → уточнения → подача → ошибка анализа → повтор с синтетической моделью → оценка с цитатой → XLSX с баллом и полным длинным ответом.
- Docker-образ собран; внутри Python 3.12 выполнены корневые unittest: 77 успешно, 34 DB-теста явно пропущены без подключения. Отдельные локальные DB-прогоны покрывают эти 34 теста.
- Проверены Compose и CLI образа; найденных ключей в изменяемом Python-коде нет.

Тесты используют только синтетические данные. Реальные VK/LLM запросы не выполнялись, рабочая Supabase БД не изменялась. Не подтверждены реальная задержка DeepSeek, стоимость работы и доступность облачного стенда. Для публикации результатов нужна выбранная командой рубрика и локальные секреты; инструкции — в README/HANDOFF.

## История и работа команды

Все исходные ветки сохраняются, их работа остаётся в истории. Локальная резервная копия до изменения метаданных: `work/before-main-integration.bundle`; она не публикуется и не входит в Docker.

После согласованного изменения метаданных коммитов старые и новые SHA различаются. Безопаснее сохранить незакоммиченные изменения и свои локальные коммиты, затем клонировать репозиторий заново. Нельзя отправлять старую историю обратно через обычный merge. Нужные неопубликованные коммиты переносятся выборочно в новую ветку от актуальной main.
