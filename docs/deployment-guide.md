# Эксплуатация и развёртывание

Рабочий адрес: https://gim-volunteer-bot.vercel.app. Сообщество: https://vk.me/club242476311. Проект Vercel: `gim-volunteer-bot`, аккаунт публикации `mchibisov`. Используется Callback API сервера №2; Long Poll как действующий обработчик остановлен.

## Облако

1. Установить Python-зависимости из `requirements.txt`; код private Repository включён из `database/src`.
2. Применить checksummed миграции `database/supabase/migrations` оператором БД; runtime использует три отдельные ограниченные роли.
3. Развернуть `api/index.py` по `vercel.json`. Настроить encrypted production-переменные из `.env.shared.example` и `VK_CALLBACK_SECRET`, `VK_CONFIRMATION`, `WORKER_DISPATCH_KEY`. Не копировать секреты в Git, логи, чат или публичную страницу.
4. Для этого облачного режима применить `deploy/supabase-dispatch.sql`. Сохранить URL `/work` и ключ в Vault с именами `gim_worker_url`/`gim_worker_key`. Создать обязательное минутное расписание `gim-worker-recovery` из комментария в этом файле. В рабочем проекте расписание уже включено.
5. Callback подтверждает VK только после транзакции записи в outbox. pg_net запускает ограниченный HTTP-worker; Cron подхватывает потерянное пробуждение, отложенную попытку или истёкшую аренду. Вне активной очереди Vercel-worker не вызывается. Завершённые формы не зависят от жизни HTTP-процесса.

Контроль: GET `/health`; `/status`, `/jobs`, пробная `/export` в VK; очередь, cron.job_run_details и net._http_response в Supabase; ошибки Vercel. Health подтверждает доступность приложения, а не всю цепочку БД/LLM — проверяйте команды и экспорт отдельно.

## Откат к Docker

Подготовлен локальный `gim-mvp-final:cloud-backup`; он понимает новые рубрики и схему. Сначала отключить message_new Callback для сервера №2 и расписание облачного диспетчера; затем запускать один gateway и worker через Compose с `GIM_IMAGE=gim-mvp-final:cloud-backup`. Не запускать одновременно два транспорта/набора обработчиков. Схему назад не удалять. Старые контейнеры и `hse-gim_shared_files` сохранены.

При повторном включении Long Poll проверить checkpoint и восстановление непрочитанных событий; не удалять очередь. Проверенный перенос в облако воспроизвёл последний Long Poll cursor до освобождения gateway.

## Ограничения эксплуатации

Бесплатные квоты Vercel/Supabase и баланс Polza надо контролировать; бесконечная бесплатная работа не обещается. Новая задача после аварии может ожидать минутное расписание и истечение аренды. При проблеме LLM анкеты сохраняются; отсутствие оценки не является нулём. Постоянное резервирование, правила хранения/удаления и официальный текст оператора персональных данных должен утвердить музей перед публичным набором.

Аватар `assets/vk-avatar.png` подготовлен; токен сообщества не поддерживает загрузку owner photo (`vk_27`). Его можно установить в управлении сообщества под администратором. Название и настройки кнопки старта обновлены через официальный API.
