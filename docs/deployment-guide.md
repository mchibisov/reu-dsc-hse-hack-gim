# Эксплуатация и развёртывание

Рабочий адрес: https://gim-volunteer-bot.vercel.app. Сообщество: https://vk.me/club242476311. Проект Vercel: `gim-volunteer-bot`, аккаунт публикации `mchibisov`. Используется Callback API сервера №2; Long Poll как действующий обработчик остановлен.

## Новая установка

Начните с [подготовки новой БД, ролей, материалов и администратора](setup-from-scratch.md). Наличие облачного проекта само по себе не означает готовности данных. Инструкция ниже выполняется после этого этапа.

## Облако

1. Установить Python-зависимости из `requirements.txt`; код private Repository включён из `database/src`.
2. Применить checksummed миграции `database/supabase/migrations` оператором БД; runtime использует три отдельные ограниченные роли.
3. Развернуть `api/index.py` по `vercel.json`. В Settings → Functions проекта установить регион рядом с БД (для действующей Supabase eu-central-1 — fra1); при API upload дополнительно передать `projectSettings.serverlessFunctionRegion=fra1` и проверить `regions` готового deployment. Настроить encrypted production-переменные из `.env.example` и `VK_CALLBACK_SECRET`, `VK_CONFIRMATION`, `WORKER_DISPATCH_KEY`. Не копировать секреты в Git, логи, чат или публичную страницу.
4. Для этого облачного режима применить `deploy/supabase-dispatch.sql`. Сохранить URL `/work` и ключ в Vault с именами `gim_worker_url`/`gim_worker_key`. Создать обязательное минутное расписание `gim-worker-recovery` из комментария в этом файле. В рабочем проекте расписание уже включено.
5. Callback сначала фиксирует событие в outbox, затем отдельным SQL-запросом будит worker и подтверждает VK. Это закрывает гонку с завершающимся worker, из-за которой команда могла ждать минутного Cron. Функция закреплена в `fra1`, рядом с рабочей Supabase `eu-central-1`. pg_net запускает ограниченный HTTP-worker; Cron подхватывает потерянное пробуждение, отложенную попытку или истёкшую аренду. Вне активной очереди Vercel-worker не вызывается. Завершённые формы не зависят от жизни HTTP-процесса.

В Supabase включите Vault и сохраните два секрета через его защищённый интерфейс:

- `gim_worker_url`: `https://ВАШ-ПРОЕКТ.vercel.app/work` (поддерживается стандартный домен vercel.app).
- `gim_worker_key`: то же значение, что `WORKER_DISPATCH_KEY` в Vercel.

Оператор применяет `deploy/supabase-dispatch.sql` к своему проекту. Затем в SQL Editor создаёт расписание, заменяя числовой пример своим VK_GROUP_ID:

```sql
SELECT cron.schedule('gim-worker-recovery', '* * * * *',
  'SELECT gim.wake_worker(123456789)');
```

Не создавайте дубли расписания на уже настроенном проекте. В настройках Callback своего сообщества VK укажите `https://ВАШ-ПРОЕКТ.vercel.app/callback`, совпадающий `VK_CALLBACK_SECRET`, код подтверждения из VK в `VK_CONFIRMATION`; подтвердите сервер и включите `message_new`. Все три runtime DSN, VK/Polza ключи и конфигурация набора должны быть в production env до подтверждения. Файлы runtime, .env и пароли в загрузку исходников не включаются.

Контроль: GET `/health`; `/status`, `/jobs`, пробная `/export` в VK; очередь, cron.job_run_details и net._http_response в Supabase; ошибки Vercel. Health подтверждает доступность приложения, а не всю цепочку БД/LLM — проверяйте команды и экспорт отдельно.

## Откат к Docker

Подготовлен локальный `gim-mvp-final:cloud-backup`; он понимает новые рубрики и схему. Сначала отключить message_new Callback для сервера №2 и расписание облачного диспетчера; затем запускать один gateway и worker через Compose с `GIM_IMAGE=gim-mvp-final:cloud-backup`. Не запускать одновременно два транспорта/набора обработчиков. Схему назад не удалять. Старые контейнеры и `hse-gim_shared_files` сохранены.

При повторном включении Long Poll проверить checkpoint и восстановление непрочитанных событий; не удалять очередь. Проверенный перенос в облако воспроизвёл последний Long Poll cursor до освобождения gateway.

## Ограничения эксплуатации

Бесплатные квоты Vercel/Supabase и баланс Polza надо контролировать; бесконечная бесплатная работа не обещается. Новая задача после аварии может ожидать минутное расписание и истечение аренды. При проблеме LLM анкеты сохраняются; отсутствие оценки не является нулём. Постоянное резервирование, правила хранения/удаления и официальный текст оператора персональных данных должен утвердить музей перед публичным набором.

Аватар `assets/vk-avatar.png` подготовлен; токен сообщества не поддерживает загрузку owner photo (`vk_27`). Его можно установить в управлении сообщества под администратором. Название и настройки кнопки старта обновлены через официальный API.

Выпуск опубликован через авторизованный API upload исходников из main. Git-метаданные отдельно натолкнулись на Vercel team collaboration check; GitHub-авторство mchibisov подтверждено, но автоматическая Git-интеграция не настроена. Последующие push в main сами по себе не обещают автоматический deploy.
