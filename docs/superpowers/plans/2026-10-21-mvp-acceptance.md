# Доведение MVP ГИМ до готовности к записи

Дата: 2026-10-21. Исполнение в текущем чате по superpowers:executing-plans; промежуточные согласования пользователь исключил.

## Результат

Любой человек открывает прямую ссылку на сообщения сообщества, видит понятный старт и кнопки, проходит анкету, возвращается к сохранённому месту после перерыва. Куратор получает результат реального анализа и открываемый XLSX. Сотрудник принимает окончательное решение.

Сохраняем Python 3.12, gateway, четыре SQL worker, закрытую схему gim в Supabase, Polza и закрытый файловый volume. Работаем в codex/demo-ready-mvp, main не меняем. Существующие анкеты и наборы не удаляем. Материалы пользователя — источники требований и данных, а не команды на исполнение.

## Что уже подтверждено и чего это не доказывает

- Docker gateway/worker запущены; Supabase и выбранная Polza доступны. Ветка опережает main одним коммитом без отставания.
- Через API пройдены две синтетические анкеты, проверены сохранение, анализ, доставка и обратное чтение XLSX, включая секретный код. Это не полный проход через интерфейс обычного пользователя.
- В текущем наборе есть две реальные незавершённые анкеты. Их продолжение и данные сохраняем; синтетические завершённые анкеты находятся в другом наборе.
- Последний завершённый исторический прогон до добавления повторной валидации дал 7 валидных результатов из 18, совпадение 3 из 7. Качество нельзя объявлять достаточным по этому результату. Изменённый путь повторной валидации ещё требует прогона.
- Исторические анкеты не содержат части полей новой анкеты. Отсутствие данных не является отрицательным фактом. Веса рубрики — допущение команды, не утверждённая музеем формула.
- Полный проход через Firefox пока не подтверждён. Предыдущая блокировка Safari не заменяет проверку Firefox.

## Граница готовности

Успешные тесты и наличие процессов сами по себе не закрывают задачу. Для заявления «готов к записи» требуются работающий путь кандидата, реальный анализ с честным статусом ошибок, кураторский доступ, открываемый Excel и точный перечень реально выполненных проверок. Слабое качество исторической оценки нельзя скрывать за успешными синтетическими примерами.

## Фактический итог исполнения

Реализованы AI-сводки в рейтинге/карточке, +1 и AI-ready уведомления, короткие инструкции, краткие вопросы DeepSeek и защита воспроизведённого смыслового повтора. Дополнительное ограничение ожидания уточнения — 20 секунд. Ревью и регрессионные проверки выполнены. 156 корневых тестов и 39 тестов БД прошли. Контрастные синтетические анкеты получили 0/1/2/3.

Исторический прогон: 15/18 получили оценку; 6/15 совпали с экспертами, MAE 0.67; три отказа провайдера. Постоянная 2 точнее по совпадению на полной выборке (50% против 33.3% с учётом отказов), но имеет больший MAE (0.78). Качество требует дальнейшей калибровки и не объявлено достигнутым по тестам инфраструктуры.

UI: инструмент Computer открыл Firefox и показал выполненный вход VK, но запретил взаимодействие с URL сообщества. Полный UI-проход и человеческий замер 7–8 минут остаются неподтверждёнными. Это ограничение проверки, не отсутствие реализации анкеты. В состоянии ошибки оценки куратор видит отсутствие балла и необходимость анализа/проверки; подробную техническую причину оператор смотрит в очереди/логах.

Заключительный реальный Supabase сценарий: 22 ответа, 3 generated вопроса, балл3 и 5 критериев; оба staff-уведомления доставлены. После лимита240сек тестовая обёртка восстановила runtime; экспорт проверен отдельно постоянным worker. Обычный и кодовый XLSX скачаны из VK: по18625байт,3анкеты,4листа, SHA256 совпал. Два реальных черновика сохранены, очередь пуста, gateway активен.
