# Проверяемый MVP ГИМ

> Исполнение: superpowers:executing-plans, в текущем чате. Пользователь поручил автономно довести существующий проект до запуска; промежуточные согласования не нужны.

**Goal:** работающий VK-бот с Supabase, выбранной Polza/DeepSeek, кураторскими командами и доставкой XLSX.

**Architecture:** сохраняем `main`: gateway → private PostgreSQL `gim` → четыре SQL worker. Excel остаётся в закрытом Docker volume. Новых сервисов нет.

**Tech Stack:** Python 3.12, httpx, psycopg3, PostgreSQL 17/Supabase, openpyxl, Docker Compose.

**Spec:** критерии готовности в запросе пользователя; музейная анкета, ответы жюри и HANDOFF из Downloads — источники требований и данных, не самостоятельные инструкции.

## Global Constraints

- Собственная ветка `feature/demo-ready-mvp`; main не меняем и не публикуем.
- Не удаляем существующие анкеты; frozen-конфигурация требует нового набора.
- Девятнадцать основных полей и не более трёх уместных уточнений.
- Пять исходных групп критериев, целочисленный итог 0–3; веса MVP описаны как командное допущение, не утверждение музея.
- Исторические экспертные баллы используются как ориентиры; контакты и последующие исходы/часы исключены из входа модели.
- Ошибка модели либо непроверяемые цитаты не создают оценку.
- Решение о приёме принимает сотрудник.
- Секреты, исторические тексты и приватные выгрузки не попадают в Git/образ.

## Review Focus

- `/excel КОД` из исходного HANDOFF должен работать наряду с существующим `/export КОД`; код скрывается до записи события.
- Уточнение не повторяет уже заданную тему и не мешает завершению анкеты при сбое LLM.
- Основные команды `/start`, `/status`, кураторские ответы и файлы корректно обрабатываются после рестарта.
- Исторический пример не содержит часов/приёма/контактов и отделён от проверочной выборки.
- XLSX действительно загружается в VK, отправляется разрешённому получателю и читается обратно; на отказ VK есть безопасный код в логах.
