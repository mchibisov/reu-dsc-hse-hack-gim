# Проверка реализации

## Принятые решения
- Последнее указание пользователя: без Redis; PostgreSQL jobs вместо ARQ.
- FSM и выбор уточнений детерминированные. Генерация персонализированных вопросов
  через LLM остаётся интеграцией команды, не имитируется.
- Экспорты используют Docker volume; S3/Supabase Storage пока не подключён.
- Рабочая ветка: feat/vk-bot-storage-export; main не изменяется.

## TDD и review
FSM, экспорт, обработка VK и проверка оценок проверены сначала RED, затем GREEN.
Независимое review Superpowers выявило три Important проблемы:
1. Отзыв прав перед отправкой /top. Исправлено recipient_id и повторной проверкой роли.
2. Перестановка исходящих сообщений. Исправлено serial_key и глобальной sequence.
3. Устаревший worker публикует результаты. Исправлено fencing перед score/export
   и отдельным именем файла для каждой аренды.
Регрессионные тесты на все три воспроизвели ошибки до исправлений.
Дополнительный тест выявил пустой VK_GROUP_ID при миграции: исправлено.

## Среда
Docker CLI доступен, daemon отсутствует. Нативный временный PostgreSQL не смог
создать shared-memory segment из-за sandbox. SQL-проверки выполнены через
PGlite 0.5.10 по PostgreSQL wire protocol. Параллельные сессии проверяются отдельно
в GitHub Actions на PostgreSQL 17; локально этот тест явно пропускается.
На первом этапе токен не был предоставлен; реальная доставка сообщений не проверялась.

## Расширение 21 октября 2026
Токен проверен без вывода в логи и сохранён только в локальном .env (chmod 600).
VK Long Poll и message_new включены, метод получения сервера успешно отвечает.
Реальная отправка сообщений не выполнялась. По последнему запросу push запрещён.
Согласие сделано необязательным по явному указанию пользователя.
Добавлены импорт исторических форм, контекстные уточнения и HTTP-интеграция
сервисов команды, меню ролей, карточка заявки, документы VK, диагностика,
разделение worker/report-worker и персистентный Long Poll cursor.

Повторное независимое review обнаружило и исправило три Important проблемы:
- Экспорт после смены CAMPAIGN: теперь используется набор из payload задачи.
- Вариант с включённым согласием и вложением в первом сообщении: сохранение
  документа разрешается после прохождения настроенного шага.
- Обновление банка вопросов во время анкеты: отображение и сохранение используют
  один снимок текстов и последовательности. Все три регрессии проверены RED→GREEN.

Проверка входных Excel импортёром: 57+55 анкет; исходные файлы не изменены,
в репозиторий не добавлены. Импорт в реальную БД пока не выполнялся.

Итоговая локальная suite: 47 тестов, 46 успешны, 1 требует настоящего
многосессионного PostgreSQL и пропускается в PGlite. Пройдены compileall,
git diff --check, pip check и проверка обеих Compose-конфигураций.
Контракты scoring/followups проверены HTTP MockTransport: это не проверка
развёрнутых сервисов команды. Настоящий VK API проверен только диагностическими
вызовами, не отправкой сообщений. Docker image не собран: daemon недоступен.

## Последовательный ИИ-диалог
По запросу пользователя удалены правила подбора уточнений по ключевым словам.
После основной анкеты и каждого ИИ-ответа следующую реплику выбирает модель по
сохранённой истории. Основные вопросы остаются музейными, итоговый анализ выполняется
после завершения диалога. Ошибка модели оставляет ответы в БД и повторяет задачу;
шаблонного fallback нет. Прямой API Mistral/OpenRouter и HTTP-адаптеры поддерживаются.

Независимое review нашло две Important проблемы. Обе воспроизведены тестами RED:
- Ещё не обработанное дополнение могло стать ответом на будущий вопрос.
  Публикация теперь сериализована с ingestion; ожидающие входящие события
  сначала сохраняются как ответы, результат по устаревшему контексту не публикуется.
- Внешний scoring adapter обходил строгую рубрику. Теперь оба пути используют
  одну зафиксированную рубрику, полный состав критериев, weights/points и цитаты.
Обе регрессии исправлены и проверены GREEN.

Итог: 60/60 тестов успешны на настоящем локальном PostgreSQL в отдельной
gim_ai_test_20261021_b8f2, включая многосессионный захват задач. Рабочая БД
не затронута. Пройдены compileall, git diff --check и проверка отсутствия ключей
в файлах Git. Настоящий API модели не вызывался: ключ/модель не предоставлены.
Имя автора новых коммитов установлено по указанию пользователя: Vova,
