# Последовательный ИИ-диалог

Пользователь одобрил поток: основные вопросы -> ИИ-уточнения по одному после
каждого ответа -> итоговый анализ всей анкеты. Ключевые слова и шаблонный fallback
для выбора уточнений удаляются. Основная анкета музея и управление FSM фиксированы.

Каждый ответ фиксируется в answers до внешнего вызова. Фоновая задача хранит
application_id и revision. Во время HTTP дополнения кандидата сохраняются отдельно,
устаревшие результаты не публикуются. Перед публикацией проверяются также ещё
не обработанные входящие события; при их наличии задача повторяется. По умолчанию
не более трёх ИИ-вопросов суммарно. Модель может завершить уточнения раньше.

Прямой API совместим с Mistral/OpenRouter chat completions и JSON mode.
Внешние FOLLOWUP_URL/SCORING_URL остаются альтернативными адаптерами.
Ошибки модели приводят к повтору задачи, без выдуманного вопроса/балла.
Критерии предоставляет человек через RUBRIC_PATH. Проверка весов, покрытия всех
критериев, суммы и цитат одинакова для обоих путей скоринга. Рубрика фиксируется
перед первым вызовом оценки, результат и основания сохраняются в evaluations.

Проверка: unit-тесты протокола и рубрики; HTTP MockTransport; интеграционные
тесты на отдельном настоящем PostgreSQL, включая повторы, дополнения и конкуренцию.
Тесты не отправляют реальные анкеты провайдеру модели и не меняют рабочую БД.
