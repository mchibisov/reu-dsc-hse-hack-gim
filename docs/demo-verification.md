# Запуск и проверка демонстрации

Проверено 21.10.2026. Основной сценарий теперь работает в Docker локально, с реальными Supabase, Polza и VK API. Ветка изменений — `feature/demo-ready-mvp` от актуального `main` (`ed0af3e`).

## Как тестировать

1. Любой человек открывает [диалог бота](https://vk.me/club242476311), разрешает сообщения и нажимает «Начать». Предварительного назначения роли не нужно.
2. Бот представляет себя, запрашивает согласие и проводит через 19 основных вопросов. Общие кнопки: «Начать», «Статус», «Помощь». Для согласия, статуса занятости и направлений есть варианты ответа.
3. В вопросе о VK показана ссылка `https://vk.com/idВАШ_ID`. Можно открыть её или нажать «Использовать мою страницу»: бот сохраняет правильную ссылку без копирования и без просмотра страницы.
4. После основных ответов — максимум три персональных уточнения. Уже заданные темы и явно раскрытые предпочтения/график не запрашиваются повторно.
5. После подачи куратор получает уведомление. Результат анализа доступен в `/top`, `/stats`, `/application UUID`. Анализ выполняется в фоне; кандидат не получает внутреннюю оценку.
6. Куратор отправляет `/export` или `/export UUID`. Бот присылает **файл `.xlsx` как документ**, а не только текст. Сообщение о подготовке файла — подтверждение запроса, само вложение приходит отдельно.
7. Доступ без роли куратора: `/excel КОД` (также `/export КОД`). Код находится только в локальном `EXCEL_ACCESS_CODE`; его не нужно публиковать или встраивать в приветствие.

VK-бот штатно работает от имени сообщества. Возможности ботов, кнопка начала, сообщения и Bots Long Poll включены через API. Старый Windows-бот отвечал параллельно и мешал тестам; пользователь подтвердил его остановку. Одновременно запускать его с текущей версией нельзя.

## Что реально проверено

- Реальный вход в Supabase тремя отдельными ограниченными runtime-ролями; private schema `gim`; все пять исходных миграций сохранены без изменений.
- Реальный JSON-ответ модели `deepseek/deepseek-v4.1-flash-1017` через Polza. Полный синтетический анализ после настройки reasoning занимал около 10 секунд в отдельном пробном запросе. Это не гарантия задержки каждого запроса.
- Два синтетических сценария «медиа» и «фонды»: по 19 основных ответов и три уточнения, подача, сохранение по 22 ответов, реальная оценка 3/3 с пятью критериями и цитатами. Входы тестового скрипта синтетические; сообщения кандидата захватывались скриптом, не отправлялись несуществующим пользователям.
- Кураторские `/admin`, `/top`, `/stats`, карточки; реальные уведомления и доставка документов только в подтверждённый пользователем VK-профиль.
- Два настоящих XLSX: обычный и по секретному коду. Оба скачаны обратно через VK API, проверены SHA-256 и openpyxl. Четыре листа: «Анкеты», «Ответы», «Собеседование», «Сводка». В тестовой выгрузке две анкеты и 44 ответа. Один файл — 22 787 байт. Приватные документы остаются вне Git.
- Реальные пользовательские сообщения принимает постоянный gateway; его аренда активна, в новом наборе создаются анкеты и готовые файлы XLSX.
- Приветствие и обе разновидности клавиатуры (навигация и собственный профиль) действительно отправлены и приняты VK API.
- Во время проверки случались сетевые обрывы Supabase и тайм-ауты загрузки VK. Сохранённые ответы не потерялись; очередь повторила работу, документы доставлены. В runtime ограничены повторы, есть heartbeat и защита от устаревшего worker. SIGTERM освобождает аренду при штатной остановке Docker.

На предыдущем этапе проверены 143 корневых теста и 38 pytest компонента БД (единственный условно пропускаемый тест параллельных подключений дополнительно выполнен с `REAL_POSTGRES_TESTS=1`); компиляция Python, Compose config и сборка Docker успешны. Независимое ревью проверило runtime; подтверждённая ошибка строгого типа needs_review исправлена и покрыта regression test.

## Данные и оценивание

Исходные таблицы содержат 112 экспертных меток: 55 анкет весны 2025 и 57 осени 2024. Распределение 0/1/2/3: 27/16/54/15. Отдельно выделены 94 анкеты для подбора восьми ориентиров и 18 для проверки. Контакты, даты рождения и последующие часы/приём/удержание не являются входами оценщика.

Пять групп и их веса заданы командой MVP по исходным критериям. При неполной информации сервер нормирует балл только по подтверждённым группам; нужно не менее 70% веса с цитатами. Неучтённые группы явно перечисляются. Ошибка модели не заменяется нулём. Один невалидный JSON можно исправить повторным запросом с теми же источниками, затем результат снова проходит полную проверку; общий SQL retry ограничен.

Повторный диагностический прогон с ограниченным исправлением JSON: **15 валидных оценок из 18 (83.3%)**, точное совпадение **6/15 (40%)**, MAE **0.67**; три отказа провайдера оставлены без оценки. Если считать отказ несовпадением, точность на всей выборке **6/18 (33.3%)**. Постоянная оценка 2 на тех же 18 даёт 50% совпадения и MAE 0.78: ошибка по величине ниже, точность совпадения хуже базовой. Качество экспертного отбора этим не подтверждено; требуется дальнейшая калибровка. После нескольких итераций эти 18 — диагностическая выборка, не независимая проверка обобщения. Веса не утверждены музеем, модель не дообучалась; решение принимает сотрудник. Прогон выполнен до последнего уточнения формулировки prompt о строгом/нормированном расчёте; формула и валидатор при этом не менялись.

Старый набор, его анкеты, тестовые сценарии и файлы не удалены. Текущий набор использует новую версию рубрики; исторические конфигурации не переписывались.

## Команды оператора

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=30
python -m gim.shared_main check-db
python -m gim.shared_main check-vk
```

`scripts.smoke_api` предназначен только для явной проверки с остановленными обычными gateway/worker. Он сохраняет синтетические анкеты и возобновляет только собственные помеченные примеры, не изменяя существующие ответы. Не запускать его параллельно с рабочим контуром. `scripts.evaluate_history` передаёт содержательные исторические тексты модели и запускается только с разрешения владельца материалов; в этой сессии разрешение получено отдельно.

Текущий сервер — этот компьютер с запущенным Docker. Отдельный круглосуточный хостинг не разворачивался. Через Safari/Firefox интерфейс не проверялся: пользователь поручил продолжить через API после блокировки Computer Use. Полная нагрузка 50 человек с реальными LLM/VK запросами не измерялась.


## Дополнительная проверка текущих изменений

- Добавлены короткая AI-сводка в рейтинге и полный анализ в карточке, уведомление «+1 анкета» после подачи и отдельное уведомление AI-анализ готов после сохранения результата. Постановка второго уведомления атомарна и идемпотентна, право сотрудника проверяется перед отправкой.
- Дополнительные вопросы создаёт реальный DeepSeek: до трёх, один за раз, до 350 символов. При сбое генерации остаётся музейная библиотека; при сбое анализа балл не создаётся. Воспроизведённый повтор о личном вкладе под другим target_slot закрыт регрессионным тестом и повторным вызовом реальной модели. Произвольные смысловые перефразы полностью словарными правилами не исключить.
- Новый полный API-прогон: две синтетические анкеты по 22 ответа, по три **generated** вопроса, по пять критериев с проверенными цитатами. Реальные Polza и VK, оба XLSX скачаны обратно, SHA256 и четыре листа проверены. Чтобы не останавливать работающий бот и не создавать фиктивных кандидатов в текущем наборе, SQL этого повторного прогона — отдельная временная PostgreSQL, конфигурация вопросов/направлений/рубрики прочитана из Supabase. Ранее два сквозных сценария прошли и на реальной Supabase.
- Автоматический ввод 19 ответов и трёх уточнений занял 13.5 и 17.1 секунды; последующий анализ — 19.6 и 12.5 секунды. Это машинные задержки, без чтения и набора человеком. **7–8 минут — целевой, а не измеренный пользовательский результат**. Анализ выполняется после подачи и не задерживает кандидата.
- Excel получил русские заголовки и статусы; полные ответы, идентификаторы, безопасное разбиение длинного текста и защита от формул сохранены.
- Последний локальный suite: **156 корневых тестов, все прошли**, включая интеграционные проверки private ролей и тест параллельных подключений; **39 тестов компонента БД прошли**. Использовалась отдельная временная PostgreSQL; рабочие анкеты не изменялись.
- Независимое ревью нашло потерю отрицания в распознавании целей; воспроизведено и исправлено с тестом. Ограничение: лексические эвристики не гарантируют распознавание всех смысловых повторов.

Короткие инструкции: [кандидату](user-guide.md), [куратору](admin-guide.md). Основной вход: [бот ГИМ](https://vk.me/club242476311).

Реальная проверка текущего набора Supabase: постоянный worker обработал команды рейтинга/сводки и выгрузку, XLSX (9890 байт) доставлен подтверждённому админу, скачан обратно и сверен по SHA256; четыре листа и русские заголовки на месте. Две существующие реальные анкеты сохранены без изменений. Дополнительно четыре синтетических профиля дали 0/1/2/3 с пятью критериями каждый; это проверка шкалы, не экспертной точности.

Для соблюдения короткого прохождения ожидание одного AI-уточнения ограничено 20 секундами; зависший провайдер отменяется, анкета продолжается через библиотеку. Регрессионный тест подтверждает завершение при зависании.


Заключительная проверка **на текущей реальной Supabase**: добавлена одна явно помеченная синтетическая медиа-анкета, сохранены 22 ответа и три generated уточнения, анализ Polza дал 3/3 с пятью критериями. Оба уведомления — о подаче и о готовом анализе — доставлены, без ошибок. Общий лимит тестовой обёртки 240 секунд прервал последующий этап кураторских команд; finally автоматически вернул постоянные контейнеры. Проверка экспорта затем завершена отдельно на постоянном worker: обычный и кодовый XLSX по **18 625 байт**, по три анкеты текущего набора, SHA256/четыре листа/русские заголовки проверены после скачивания из VK. Очередь пуста, аренда gateway активна. Две реальные незавершённые анкеты остались с прежними ответами и текущими вопросами. Демоанкету можно увидеть в `/top`; она прямо подписана как синтетическая.
