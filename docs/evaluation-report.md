# Качество оценивания — 22.10.2026

## Вывод

**Улучшение независимой точности не подтверждено. Новый классификатор не включён по умолчанию.** Старые анкеты сохраняют закреплённую рубрику и предварительную оценку сотруднику; новый отчёт добавляет проверенные факты, цитаты и явные пробелы. Автоматического решения о приёме нет.

## Данные и независимость

112 экспертных меток: 2024 — 57, 2025 — 55; классы 0/1/2/3: 27/16/54/15. «Вектаризованные данные» — копия тех же ответов с тремя бинарными признаками команды; это не embeddings и не дополнительные независимые анкеты. Сумма трёх признаков совпала с экспертным баллом в 53/112 случаях (47,3%). Метки и исходные содержательные ответы сопоставлены; оформление курса изменено, даты рождения 2025 представлены иначе.

Финальный контроль: 22 записи (5/3/11/3 по классам), seed=42, распределение по годам и классам. Из кандидатов в контроль исключены прежние 18 диагностических, восемь исторических few-shot примеров и индивидуально просмотренные записи. Разработке доступны 90 записей. Точных дубликатов и пар с TF-IDF cosine >0.92 в этой выборке не найдено. Будущие запуски при близких дублях останавливаются до разбиения. Просмотренные ранее анкеты допустимы в development, но CV не выдаётся за независимый финальный результат.

Признаки: только сведения, доступные до отбора. ФИО, контакты, дата рождения, фактические последующие часы, принятие и удержание исключены из внешних запросов. Пользователь отдельно разрешил обезличенную передачу всех 112 анкет в Polza. Свободный текст проверяется редактором контактов, но может содержать личные подробности; сырые данные и индивидуальные прогнозы в Git не входят.

Сравнены C=0.1/1/10, с балансировкой и без неё, Ridge alpha=1/10/100. Три группы команды сопоставлены с пятью музейными: мотивация, опыт, нагрузка, качество анкеты, логистика. Для каждого из 15 заранее определённых фактов: да / нет / неизвестно; да и нет требуют точной цитаты. Неизвестно кодируется нейтральным нулём, без утверждения об отсутствии навыка. Итог экспериментальной модели — argmax четырёх фиксированных линейных откликов; LLM его не назначает. Это не вероятность.

Few-shot и TF-IDF RAG сравнивались на одинаковых 12 сбалансированных development-примерах, без контрольных записей в примерах. Первая конфигурация оказалась медленной; затратный эксперимент ограничен 60 секундами на вызов, 3500 выходными токенами и отключённым reasoning. Варианты часто не проходили порог подтверждённого веса групп. Эти ограниченные прогоны **не эквивалентны полной production-цепочке с исправлением JSON** и не служат доказательством её нулевой точности. RAG не внедрён. Гиперпараметры фиксированных фактов выбирались по общей CV на 90, а не по сбалансированным 12.

Fine-tuning: выбранный DeepSeek реально есть в каталоге Polza; embeddings endpoint проверен. Поддержка дообучения именно этой модели через Polza не подтверждена публичной документацией. Обучающие задания не создавались; преимущества fine-tuning не заявляются.

Основные проблемы: мало классов 1/3, неоднородность годов, неоднозначная связь бинарных признаков с оценкой, недостаток исторических сведений по нагрузке и логистике. Прогноз тяготеет к классу 2. Прежние ~40% получены на другой, уже использованной при доработках диагностической выборке; напрямую сравнивать их с этими 45,5% нельзя. Исходная production-цепочка отдельно воспроизведена с закреплённой рубрикой, reasoning low, лимитом 6000 и штатным исправлением JSON: 9/22 (40,9%), MAE 0,714. У нового гибрида на один точный ответ больше, но MAE хуже и результат ниже majority baseline; оснований для замены нет. После финального прогона модель не настраивалась. Для доказанного улучшения нужны новые независимые экспертные анкеты и уточнение рубрики, а не подгонка под эти 22 записи.

## Воспроизведение

`python -m scripts.evaluate_final prepare|development|select|final` — опциональный эксперимент с доступом к локальным материалам и API. `select` воспроизводит сравнение фиксированных моделей; `python -m scripts.evaluate_embeddings` — диагностические embeddings только development. Пути задаются `GIM_MATERIALS_DIR` и `GIM_ENV_FILE`. Нужны изолированные numpy/scikit-learn; они не добавлены в Docker бота. Разбиение, параметры, индивидуальные результаты и кэш лежат приватно в `runtime/final-evaluation`. `final.json` запрещает повторную настройку; первый малый development-selection сохранён отдельно, окончательный выбор по общей CV зафиксирован до финала. Полный production baseline проверяется отдельно с оригинальной закреплённой рубрикой, reasoning low и одним исправлением JSON; сокращённый эксперимент не заменяет его.

`config/final-rubric.json` — **экспериментальная** фиксированная модель без исходных ответов. Этот экспериментальный файл не включён. По более позднему прямому требованию пользователя новые анкеты используют `config/ranking-50-35-15.json`: фиксированную бинарную формулу 50/35/15, без обученных коэффициентов. Эта замена является продуктовым решением пользователя, а не результатом улучшения accuracy на контроле. Проверка двух синтетических профилей дала S=2.415 и 1.830 (оба округляются до 2), задержки анализа 65.59с и 15.88с. Это проверка реального API и арифметики, не измерение экспертной accuracy. Новая формула не выдаётся за независимо проверенную на прежних 22 анкетах; они уже раскрыты. Старые оценки не пересчитываются.

## Ограничение происхождения меток

QA называет их оценками после обработки анкеты, а Word-описание упоминает оценки, проставленные вручную на собеседовании. Не установлено, имел ли эксперт дополнительные сведения, которых нет в сохранённом тексте. Поэтому точное восстановление всех экспертных решений только из анкеты не гарантируется. В исторических таблицах также нет полного набора новых полей о занятости и планируемом времени; их неизвестность нельзя заполнять последующими часами участия.
