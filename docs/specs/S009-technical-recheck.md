# S009 — повторная техническая приёмка

Запрос: независимо перепроверить решение по IT-критериям, возможность запуска и работу бота, после проверки повторно проверить удалённое и затем повторить проверки. Базовое состояние: main23e05ba, snapshot7d06b60. Модель не меняется, production-данные не используются.

Критерии: свежий полный прогон на отдельной пустой PostgreSQL; независимый read-only review удалений/entry points; запуск из Git-архива без незакоммиченных файлов, повтор миграций/полного набора/CLI; действительный старт worker на синтетическом наборе с ограниченными LOGIN; проверка Docker и публичного health без отправки VK-сообщений. При недоступной инфраструктуре зафиксировать границу, не объявлять локальные проверки production-приёмкой. Доказательства сохраняются отдельно для каждого запуска.

IT-оценка различает запуск, соответствие сценарию, качество оценки, интеграцию и удобство. Автотесты не доказывают экспертную точность AI или человеческое удобство. Проверить, что импорт/экспорт,18 основных вопросов, факультет/направление, сохранение ответов и права доступа сохранены.

Подтверждённые исправления при приёмке: ingress должен учитывать последний реально показанный skipped-вопрос, пока следующий не показан; поздний ответ не меняет предыдущий ответ. Нагрузочный скрипт должен распознавать динамическое количество вопросов, использовать отдельный локальный TEST_DATABASE_URL и selector loop на Windows. Изменения миграций задним числом не требуются.
