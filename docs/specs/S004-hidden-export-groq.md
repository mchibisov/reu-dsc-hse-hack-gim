# S004: скрытая выгрузка Excel и Groq в текущем VK-боте

Основание: пользователь подтвердил, что доступ к Excel получает любой знающий код, а в анкете не должно быть вопроса/подсказки «введите секретный код»; затем поручил подключить Groq по предоставленному ключу.
Объём текущего изменения: работающий `gim_bot/` (ветка codex/gim-mvp), без миграции реальных анкет в неподключённый Supabase. S003 остаётся отдельной интеграцией с незаполненными cloud DSN; её возможности не выдаются за работающий запуск.

- R401: скрытая команда `/excel КОД` принимается до обработки анкеты; корректный код даёт только одноразовую выгрузку Excel в личный диалог, не общие права администратора. Обычные /top /candidate /stats остаются закрытыми.
- R402: в основном опросе/общей помощи/клавиатуре нет подсказки о коде. Код не сохраняется как ответ, в MessageEvent/LLM/logs; получатель определяется реальным from_id, групповые чаты исключены. Неверный/пустой код не создаёт export; ограничение попыток, constant-time сравнение. Повтор события не дублирует выгрузку, смена кода отзывает ещё не отправленные разрешения.
- R403: каждое принятое сообщение анкеты сохраняется до ответа; Excel не требуется для записи в БД. Реальная read-only проверка обнаружила2completed/36основных полей в локальной gim.db; в отчёты не включать реальные ответы.
- R404: ключ Groq только в игнорируемом .env; официальный endpoint api.groq.com/openai/v1. Проверить models и generation на synthetic данных, затем реальный Provider analyze/followups со строгой схемой и цитатами. Использовать фиксированные пять групп; не заявлять музейное утверждение числовой шкалы. При ошибке сохранять анкету, библиотечные уточнения и отсутствие оценки.
- R405: после тестов перезапустить ровно один управляемый VK процесс с сохранением БД и rollback. Не анализировать уже полученные реальные анкеты повторно без отдельного поручения; подключение применяется к новым завершениям. Кандидату — только подтверждение, не score/summary.

Код доступа генерируется локально и хранится в .env; пользователю сообщается его локальное расположение, в Git и отчёты код не входит. Удаление сообщения из VK не требуется: пользователь уточнил, что скрывается вопрос о коде, а не отправленное им сообщение.

Уточнение пользователя: вместо основного Groq выбрать Polza, endpoint https://polza.ai/api/v1, точный model ID deepseek/deepseek-v4.1-flash-1017. Сначала проверить доступность и существующий Provider; не заменять указанную модель другой молча. Ключ и .env не публиковать. Ранее успешный Groq smoke остаётся отдельным результатом, не доказательством Polza.
