# План S002: MVP VK-бота ГИМ

> Для исполнителя: использовать Superpowers executing-plans и test-driven-development; итоговое независимое ревью обязательно. Пользователь явно поручил начать MVP, дополнительный выбор режима исполнения не требуется.

- Спецификация: [S002](../specs/S002-gim-vk-bot.md).
- Статус: в работе.
- Цель: сквозной опрос в ВК с персональными уточнениями, оценкой и Excel.
- Архитектура: bot + внутренний gateway + масштабируемые workers, PostgreSQL и Redis. Локальная SQLite только для быстрых тестов; production — PostgreSQL.
- Стек: Python 3.12, FastAPI, httpx, SQLAlchemy async, asyncpg, aiosqlite (тесты), ARQ, openpyxl, pytest.
- Каталог реализации: `gim_bot`, ветка `codex/gim-mvp`; корневая папка проекта сама не является Git checkout.

## Общие ограничения

Все тексты на русском. Пять групп критериев. Оценки 0–3, `null` при отсутствии аналитики. Без сайта, профиля ВК, PDF, файлов резюме, ручного редактирования результатов. Персональные исходники остаются вне Git. Потеря очереди не теряет сохранённую заявку. Цели 5–7 минут и 90 пользователей не объявлять достигнутыми по unit-тестам.

## Фокус ревью

1. Повтор события и параллельные сообщения одного кандидата не продвигают FSM дважды.
2. Отказ после сохранения, до постановки в очередь или уведомления восстанавливается.
3. Формула Excel и prompt injection внутри пользовательского текста остаются данными.
4. JSON с неправильной цитатой/направлением/критерием не становится достоверной оценкой.
5. Экспорт, карточки и удаление недоступны чужим ID и общим чатам.

## Зависимости и риски

Нет VK/LLM-ключей и выбранного сервера. Docker не обнаружен в текущей системе. Исходная `.venv` проекта повреждена, используется отдельная среда на bundled Python. Новая рубрика предварительная; точность сравнения зависит от актуальной версии данных и экспертных меток. Реальные лимиты VK и модельных провайдеров проверяются при настройке запуска.
